# 直接填写 API 的 AI 修图窗口

0.3.0a3 新增可选桌面入口。无需另外安装聊天客户端：填写 API 地址、密钥和模型，输入需求即可分析当前照片或在副本修图。底层继续使用原有 MCP 工具、串行 owner 和 C1 原生接口；原七个 MCP 工具保持兼容。

**验证状态：本机 C1 副本读写、回读、原生预览和蒙版分析已通过。尚未使用真实云端密钥完成模型端联调，不把离线协议测试算成云端验收。** 目前仅支持 Responses API；只提供 Chat Completions 的兼容服务暂不能直接使用。

## 安装与启动

已配置过本项目的用户，在项目目录运行：

```powershell
.\Install.ps1 -EnvironmentOnly -WithAI -WithScopes
.\AI.ps1
```

`-WithAI` 安装 OpenAI Python SDK、Qt，并增加“Capture One AI 修图”桌面快捷方式；`-WithScopes` 安装波形图依赖和原有两个桌面入口。已有原生桥接与 Session 配置不需要重做。没有运行 C1 时，仍先使用 `Start-CaptureOne.ps1`，打开已配置的 Session 并选中照片。

也可运行 `c1ai-ai` 或 `python -m c1ai.ai_window`。窗口重复启动会唤起同一个用户窗口，不创建两个并行修图控制器。窗口关闭不会卸载 MCP 或关闭 C1。

## API 配置与动态查询

1. 点击“API 设置”，填写服务地址和密钥。OpenAI 官方地址为 `https://api.openai.com/v1`；其他地址必须实现相同的 Responses 图片输入与函数调用协议。
2. 点击“读取模型”，程序调用该服务的 `/models`；没有内置模型列表，不根据型号名称猜测能力。服务不提供列表时可手动填写其模型 ID。列表可能包含纯文本、音频等模型，出现在列表中不等于能处理图片与工具调用。
3. 选择模型，点击“查询思考等级”。先读取服务的模型元数据／详情。如果没有等级字段，发起一次带特殊无效 effort 值的极小文本请求，读取服务器校验返回的支持列表。未返回列表就显示未知，不填入固定等级。
4. 服务返回的等级会标注来源，**并不等于已逐项验证**；有的服务返回的是协议级枚举。等级留空表示不发送 `reasoning.effort`，采用该模型的服务端默认值。也允许填写服务文档明确提供的值，再用“测试连接”核对当前模型和等级组合。
5. 保存后可测试连接。测试只验证文本 Responses 请求；图片与工具能力需要首次“仅分析”实际验证。错误会显示认证、权限、额度、地址或协议问题，不自动切换模型／等级，也不自动重试扣费请求。

模型、思考等级及可用权限以账号和所填服务的实时响应为准。换 API 地址会清空旧密钥及模型列表；换模型会清空旧思考等级。查询等级可能消耗很少的额度：规范服务通常拒绝无效值，但部分兼容服务会忽略它并执行文本请求。

OpenAI 的模型列表主要返回标识和归属，不是统一的模型能力注册表；思考等级依模型不同。依据：[List models](https://developers.openai.com/api/reference/resources/models/methods/list)、[Reasoning models](https://developers.openai.com/api/docs/guides/reasoning)。本项目不会把文档里的通用候选等级冒充账号实际返回值。

## 使用

- **仅分析**：查看原生预览，按需求读取整图、蒙版、ROI 和色彩统计，不修改照片参数，也不创建副本。
- **在副本修图**：本次对话第一次编辑当前照片时创建并登记变体副本。随后同一副本继续修改，不为每个模块或每句话重复复制。新对话或换图后会重新准备副本；修改 API 设置仍保留当前副本记录。换服务、账号或模型时清空旧对话，单独调整思考等级或密钥保存选项不会清空对话。
- **波形图**：打开或重用既有分析窗口，仍可使用蒙版分析、矩形 ROI 和肤色参考方向。
- **停止**：不再派发后续操作；已经发出的 C1 调用等待结果，不强杀 C1，也不声称自动撤销已完成修改。网络无响应时可能需等 90 秒请求超时。

示例：“先分析人物和背景的明暗与颜色关系，再调整为温暖、自然的秋日氛围，保留肤色。”或“只分析当前皮肤蒙版，在矢量图里看色相方向和饱和度，不修改。”

AI 读取图层后再决定全局或局部编辑，按需使用白平衡、曝光、HDR、色阶、曲线、混色器、色彩平衡和蒙版。数值只辅助判断，程序不按肤色参考线自动将所有肤色调成同一个颜色。所有正常读写仍走原生模型接口，图片来自 C1 渲染器。

## 安全、数据和用量

- 原 RAW 和原变体保留，写入仍需登记副本、当前实例／文档／变体／图层及观察凭据；没有取消原有保护。
- 每轮绑定当前照片和变体；原生写入前核对目标。用户中途切图后停止，不跟到另一张图继续改。
- AI 没有终端、任意文件读取或网页工具。只调用现有 MCP 的 context、read、adjust、preview、operations、analyze_image；副本由本地控制器通过 images 创建，模型不能自行翻页或反复创建。
- 结果未知／部分完成或修改被拒绝时停止，保留原操作编号；不换编号自动重放。原生预览等待最多做三次只读获取，不重新创建副本或重放参数。
- 原生预览、统计、必要的身份信息（包括文件名和路径）、工具结果及聊天文本会发送到所填 API。不会上传 RAW 原文件。代码设置 `store=False`，但服务方仍按其数据政策处理请求，不能据此承诺零保留。
- 密钥默认仅在当前窗口内存中使用；勾选保存时用 Windows DPAPI 按当前用户加密，存于 `%LOCALAPPDATA%\CaptureOneAI\ai-settings.json`，不进入仓库。取消勾选再保存可删除保存的密钥。配置中的加密密钥绑定 API 地址，不会自动用于其他服务。
- API 失败仅显示经过筛选的错误，不显示可能含密钥的原始响应体。不会把 API 密钥加入系统提示词、照片操作记录或日志。
- 对话只在内存中保留最近四轮文字；每轮重新获取照片和凭据，不继续使用过期工具状态。窗口关闭后聊天不持久保存，C1 既有操作记录仍保留。
- 默认每轮最多 24 次模型请求，每次输出上限 4096 tokens，界面显示累计输入／输出 tokens，不把它冒充精确费用。API 自动重试关闭。

## 实现与验证记录（2026-10-30）

`ai_window.py → ai_agent.py → 既有 FastMCP 工具注册与调用 → client/owner/Core → WindowsBackend → C1`。

通过 FastMCP 的公开工具元数据和调用方法复用 schema、图片块和执行处理；没有添加第二套调色参数，也不向公网暴露本地 C1。OpenAI Responses 接口只做视觉判断及函数请求。工具图片按 API 的 input_image 格式回传；推理上下文在单轮内保留，聊天跨轮只保存文字。参见 [Function calling](https://developers.openai.com/api/docs/guides/function-calling)。

本次检查：

- 离线控制器：图片输入/工具结果转换、动态模型／等级解析、只读禁止修改、切图拦截、未知写入不重发、取消和副本复用。
- 本机 Windows DPAPI：加密保存／恢复、地址绑定、删除保存的密钥。
- 实际 C1 16.8.6.3784：通过新控制器创建副本，修改当前层曝光、回读、取得原生图片、读取相同副本的蒙版矢量数值；随后用完整模块快照精确恢复参数，并恢复原选中变体。原版本参数未改变。
- 发现并处理了新副本首次预览可能过期的情况；仅对只读预览做有限重取。手动曝光读回含额外小数，不能直接加数后作为精度合规目标；实测用允许精度调整，恢复使用原有模块快照粘贴，避免舍入改变原值。

尚待验证：真实密钥下的模型列表与思考等级发现、模型对图片和数值的理解、连续工具调用及审美结果；第三方 Responses 兼容服务；不同 C1 版本。API 活动额度是否适用、哪些模型可用及有效期，由账号与活动规则决定，程序不保证活动资格。

### 代码复核修正（2026-10-30）

- 最终回答先核对当前照片身份和必要的修改后预览，再显示；响应中断、切图或预览失败时不提前输出“完成”结论。网络仍按流读取以响应停止操作。
- 普通 read 直接使用其原生返回身份核验，取消之前额外的空字段预读；结束时复用同一次读取结果。回归用例中的三次必要读取不再变成六次，写入的原生原子校验保持不变。
- API 设置变更保留副本记录；新任务清空旧图片和旧用量，避免取图失败后显示上一张照片。
- 更换密钥或地址清空旧账号的模型／思考等级缓存和可编辑文本；已取消的连接测试不再显示成功。
- 配置字段类型、API 地址端口和解密结果校验失败时返回可处理的提示，不因错误类型直接退出窗口。
- 12 项针对性回归通过，包括 Qt 窗口状态；云端模型实际联调仍待有效密钥。这些修正未更换 C1 原生执行器，也未重复进行参数写测。
