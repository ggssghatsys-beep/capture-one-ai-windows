## 后续原生像素、紧凑窗口与色彩空间

- 本机反射确认 `ImageCoreBitmap` 提供 Data、Stride、Width、Height 和位图深拷贝接口。新分析使用其深拷贝／CopyPixels，避免指针寿命和像素排列猜测；原渲染／目标／修订保护均保留。
- 同一修订的 PNG 与 BGRA8 转换到规范化 RGBA 后像素 SHA-256 完全相同；实测 1600×1067、每行 6400 字节、顶行在前。离线彩色 2×2 图验证通道顺序和行顺序，损坏长度拒绝。
- 同图热缓存代表性原生时间：PNG 编码／校验／写入约 0.085–0.087 秒；无压缩像素复制约 0.016–0.018 秒，校验／写入约 0.008–0.009 秒。两条路线依次运行的 C1 渲染缓存条件不同，不把首次 PNG 1.25 秒与热态 BGRA 0.036 秒相除宣称提速倍数。缩短原始缓冲查询间隔后，本机一次热态原生取图约 0.082 秒；不是手动调整到呈现的总延迟。
- 旧 PNG preview 之后进行 BGRA 分析，原 PNG 的 map_points 仍返回 completed。两种传输的 native job 缓存分别保留，兼容既有预览语义。
- 小窗口 400×220 时图表区域 392×183，详细面板默认隐藏；主窗口可继续缩到 320×160，缩放只影响显示。
- sRGB 红色转 Display P3 的独立预期约 [234,51,35]，转 Adobe RGB 约 [219,0,0]，8 位误差不超过 2；带 P3 ICC 的纯绿色转换到 P3 保持 [0,255,0]，证明没有先裁进 sRGB。不同空间缓存分开，跨空间参考差值被拒绝，返回预览带目标 ICC。15 项针对性检查通过。
- 色彩设置不改变 C1 原生取图的源 ICC 未确认限制，不宣称扩展了 C1 原图的可恢复色域。取图与原始缓冲证据位于本地忽略目录 native-bitmap-api.json、native-rgb-vs-png.json、native-rgb-warm.json，界面检查为 compact-window.png。

`tests/test_image_analysis.py` 的 11 项检查通过：

## 延迟优化（最后实施）

保持完整图像范围和 1600 像素长边策略：

| 测量 | 结果 |
|---|---|
| 优化前单图：解码、统计、波形及 PNG | 约 2.05 秒；其中外部 FFmpeg 绘图约 1.01 秒 |
| 优化后同图首次计算 | 约 0.91 秒，含首次加载绘图库 |
| 优化后同图后续计算 | 约 0.50–0.53 秒 |
| 数值一致性 | 同样本所有直方图计数完全一致；其他数值最大绝对差约 1.42×10⁻¹⁴，浮点舍入量级 |
| 无变化的原生检查 | 约 0.008 秒；不重复取图和绘图 |
| 冷启动整条请求 | 实测约 1.73 秒，包含 owner／依赖初始化，不承诺所有机器一致 |
| 最终真实曝光改动＋回读＋新图＋波形 | 窗口同时开启时约 **0.95 秒**；写入与参数回读约 0.15 秒，取得更新的分析和波形约 **0.80 秒**。像素确实变化，完成后恢复参数 |

改动包括：用 PyAV 在进程内复用 FFmpeg 滤镜，取消每帧启动程序；仅在请求预览时编码规范化 PNG；使用低压缩级别缓存图表；RGB 数值通过精确计数和累计计数求分位数，线性转换使用 8 位查表；相同 ROI 规范化缓存键；窗口 200ms 检查修订，仅保留一个在途请求。渲染变慢或选择正在变化时保留旧结果并标记过期，不以牺牲新鲜度换速度。

这是本机单张照片的少量代表性测量，不是全目录延迟分位数，也不是逐帧实时承诺。复杂蒙版、机器负载和 C1 自身渲染仍会增加等待。

后续用户实际反馈约 3 秒延迟，不能用上述单次请求数据代替操作体感。排查发现窗口把连续调整造成的旧修订丢弃、原生渲染忙碌等正常更新状态也套用了断线的 1500ms 等待。现改为 50ms 重试；真正连接失败仍退避 1500ms，身份与修订检查不变。新增回归检查覆盖原生异常原文；窗口在本机状态目录 `scopes-latency.json` 保留最近 32 次更新记录，区分请求耗时、控件更新耗时和阶段耗时。控件更新耗时不等于显示器扫描完成时间；不据此声称已测得用户动作到屏幕呈现的全部时延。此修正后需结合实际拖动记录判断剩余延迟。

第一次窗口修正后用户仍反馈延迟，实际日志显示原生异常被包装成笼统的 `C1 internal model call did not complete`，仍触发 1500ms 退避。分析层现提取异常详情，只对明确的渲染更新冲突快速重试，不改变编辑接口的异常契约。用户再次测试反馈“明显更快”；本机记录的后续成功请求约 0.58–0.76 秒，控件更新约 10–14ms，原生渲染忙碌及修订过期均按 50ms 重试。冷启动单次约 2.47 秒，不能混入热更新速度。

随后去除统计与绘图重复的亮度量化：同一原生样本的全部数值和直方图逐项完全一致，暖态绘图从约 0.11 秒降到约 0.04–0.05 秒，统计＋绘图约 0.25–0.26 秒；检查间隔从 200ms 改为 100ms。13 项针对性检查通过。更短间隔及量化复用已加载到窗口，但不把离线改进等同于已复测的完整手动调节时延。记录为 `latency-user-before-unwrapping.json`、`latency-user-confirmed-faster.json` 和 `performance-round2.json`，均在被忽略的本地 artifacts 中。

置顶与后续排查：窗口添加可保存偏好的置顶开关，Windows 实际 HWND 的 WS_EX_TOPMOST 按开启→关闭→开启变化正确。合并重复刷新定时器，缓存当前波形 pixmap；目标切换的原生拒绝保留校验并快速重新读取，短暂 main form not ready 改为 200ms 检查，真正断线仍退避。13 项针对性检查通过。随后归纳最近 9 次有效新图请求，原生取图中位 0.2866 秒、最高 0.6329 秒，数值统计中位 0.2066 秒，解码中位 0.0517 秒，控件更新中位约 0.0099 秒；请求中位约 0.609 秒。原生取图尚未细分 C1 渲染、PNG 编码／传递与等待，所以这里只定位到取图环节，不能全部归因于 GPU 或 C1 渲染内核。

## 矢量图与启动入口（2026-10-30）

复用 OpenRV Web 的 MIT 坐标／标尺核心，21 项针对性检查通过。当前选中照片只读取图为 1067×1600，1,707,200 像素；矢量图和 get 回读的 summary 完全一致。实际原生图像显示白点云、肤色参考箭头、六色色相标记；后续外围换成由同一 Cb/Cr 投影反算的彩色色环，静态色环按色彩空间缓存，数值不变。平方像素显示保持长宽比。一次最终独立读图＋计算＋绘图请求约 0.416 秒，不能当作拖动到屏幕的端到端延迟。

优化删去矢量图每帧的整图浮点 RGB 复制和两次矩阵乘法，使用与上游三位系数等价的整数运算；直方图在已有完整数值时复用其计数。窗口重复启动通过当前用户本地消息复用，窗口关闭停止轮询；已有 owner 与 MCP 保留。新增启动器实测未重启 C1。旧的 outcome_unknown 记录经过只读查询，属于早于当前辅助进程的历史错误；没有重放或删除。
