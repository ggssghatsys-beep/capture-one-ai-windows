## 日常入口

首次在另一台 Windows 机器安装时，运行 `Install.ps1` 即可配置自动会话绑定，无需预先填写原电脑的 Session 路径。依赖仍由安装脚本安装。Capture One、Python、PowerShell 和 .NET 由用户机器提供。

首次部署这套入口后，将生成的 `config/mcp-server.local.json` 重新导入 MCP 客户端，使其通过固定的 `MCP.ps1` 启动；后续选包在这个固定入口后完成。旧配置直接启动某个虚拟环境的 Python 时，需要先完成这一次入口更新。

`Start-CaptureOne.ps1` 按运行实例、注册表安装信息、标准目录查找 C1；也保留 `-CaptureOneExe` 指定路径。读取 EXE 的数字版本、PE 架构和相邻的 runtimeconfig，匹配 `config/bridge-compatibility.json` 中明确列出的适配器。多个实例或安装位置存在歧义时要求选择。

本次清单只登记 Windows x64 / C1 16.8.6.3784 / .NET 10；这是现有功能与取图修复的验证基线。本机发现、匹配与会话切换已实测；在线包更新及其他环境仍待实测。Mac 的现有实现随源码保留，本次自动匹配和更新入口仅改 Windows。

## 自动更新的边界

- C1 正在运行时，默认启动入口直接返回，不编译、不换桥、不打开额外窗口。
- 更新前和切换前都检查 C1 与后台 owner 已结束。不自动结束 owner，不重放未完成操作。后台 owner 仍运行时延后更新，正常启动继续使用本地匹配包。
- `-Restart` 保留用户明确要求正常关闭 C1 的入口；不会强制终止进程。仍需先结束后台 owner 才可更新。
- 优先使用本地匹配包；每天检查一次项目 GitHub Release，`-CheckBridgeUpdates` 强制检查，`-NoBridgeUpdate` 完全跳过网络。
- 只接受带 `BRIDGE-COMPATIBILITY.json` 的完整发布包。按 C1 精确版本、架构、运行时、协议和色彩约定匹配，不用全局最新 ZIP 替换当前桥。
- Python 核心和原生源码作为完整包一起准备。ZIP 总哈希、逐文件哈希、内外兼容清单和 Python 版本均需一致。
- 下载先存 `.bridge-cache/<包哈希>/`，安装独立虚拟环境后才切换 `config/bridge-selected.local.json`。失败时保留原入口；源码包中不带开发机器上的桥 DLL。
- MCP、CLI、AI 窗口和波形图通过同一选包入口启动。MCP 配置由安装脚本指向固定的 `MCP.ps1`，无需每次更新手改客户端路径。
- 网络不可用时，匹配的本地桥继续使用；找不到已验证适配器时报告当前版本，不自动放开写入版本限制。
- 本次没有上传发布资产；现有旧 Release 不含新兼容清单，将被跳过。后续发布新版本时，打包脚本生成清单，发布工作流随 ZIP 上传该文件。

桥构建缓存的标识包含原生源码、适配器、C1 版本、架构、目标框架、所选框架版本与兼容清单哈希。启动钩子允许的引擎目录仍是本包 `internal/bin`，没有扩大程序集加载范围。`internal-engine.json` 通过临时文件原子替换发布。

## 自动绑定当前 Session

默认 `session_binding=auto`。先向当前用户的已认证原生桥读取 PID、进程开始时间和主窗口句柄，再以 Win32 只读证据核对实例。桥在 C1 UI 线程读取主窗口当前绑定的原生 Document Path 和 UUID；不从窗口标题、最近使用列表或旧配置推断 Session 路径。

单独的只读 `session` 命令不依赖选中照片。打开 Session 后尚未选片，可以先建立会话绑定；读取照片参数仍需单选照片。

会话绑定只保存在 owner 的内存中。切换 Session 时更新运行时绑定，避免多个客户端交替改写 config.json。每次新绑定带一枚代次标识，并加入观察令牌；结构化工具在写入前另外核对该绑定。旧会话的参数令牌与导航令牌不会被当成新会话授权。

候选登记、操作日志和请求 ID 维持原规则：切换 Session 不迁移候选写入资格，不把未完成动作提交到新 Session。副本、参数操作仍检查文档 UUID。自动绑定只覆盖 Session，Catalog 会明确提示尚未启用。

## 波形图共用同一接口

Windows 的桌面 `Scopes.ps1`、API 的 `open_window`、`c1ai-scopes` 和直接模块启动均接入同一版本包选择。API 打开窗口会经过匹配包内的 `Scopes.ps1`，控制台入口也会转到匹配包的 Python 环境，不再沿用旧调用方的环境。

波形图仍通过共享 owner 的 `analyze_image` 读取原生图像，和 MCP 共同使用 Session 路径、UUID 与绑定代次。界面不需要另外填写桥路径或旧 Session 路径。切换 Session 后，旧图表、参考、待处理 ROI 请求和框选区域会清除，重新获取当前会话；尚未选图或正在渲染时显示等待状态，不把旧会话图表当成当前结果。详情中显示 Session 名称。显式打开文件的预览保持文件模式。

需要固定会话时，在用户确认可更改配置后使用：

```powershell
.venv\Scripts\python.exe scripts\configure.py --session 'D:\Photos\MySession\MySession.cosessiondb' --pinned
```

去掉 `--pinned` 重新配置即恢复自动跟随。配置写入沿用现有 owner 运行时拒绝修改和备份机制。

## 用户允许测试后的验证顺序

1. 先合并前核对原工作区与源码副本的差异，保留另一会话新增的取图修复；不覆盖之后出现的改动。
2. 在离线临时目录检查版本匹配、错误色彩约定、未知版本、ZIP 路径、哈希、缓存及失败时的原包保留。再检查 PowerShell 入口与本机构建。
3. 保存用户工作、正常结束 C1 与 owner 后，首次通过新启动钩子打开 C1。本次增加 session 命令和主窗口握手字段，首次验证需要加载新启动钩子。
4. 先只读：未选照片时绑定 Session；读取已选照片；原生 PNG 与分析像素继续满足 `native-srgb-v1`。
5. 打开另一 Session，核对路径和 UUID 自动更新；用旧观察令牌发起请求应在写入前拒绝。再检验切回、同名不同目录的 Session、多实例和固定模式。
6. 用独立测试 Session 的登记候选做一次有意义的参数修改、原生读回与预览检查。用户原照片和正在使用的 Session 不作写入测试。
7. 最后验证版本更新失败/离线、统一入口选包，以及第二台机器的路径和运行环境发现。完成后再评估部署。

安装时 `-Offline` 使用已有依赖并关闭构建隔离；需要预先具备 setuptools 77+。`-NoDesktopIntegration` 可安装 AI/波形依赖并生成 MCP 配置，同时跳过桌面快捷方式和自动启动偏好的写入。`internal/build.ps1 -PrepareOnly` 仅编译，不发布运行中的引擎指向。

当前记录覆盖本机安装、编译、离线检查和本文开头列出的实机检查。其他机器、其他 C1 版本和未覆盖边界仍按上列步骤验证。
